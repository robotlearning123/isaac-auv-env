# OceanScale 网站设计 Brief

Opus + GPT 联合分析. 2026-05-24.

---

## 谁在看这个网站？

按 POSITIONING.md §6:
- **主要:** 做水下机器人的技术团队 (工程师, CTO)
- **次要:** 投资人, 潜在合作方

他们来到这个页面时的状态:
- 可能刚听说 OceanScale, 或从 GitHub/论文/社交媒体点过来
- 有 30 秒判断"这是什么, 跟我有没有关系"
- 不想看文档, 想看结论

---

## 网站的唯一任务

**让访客在 30 秒内理解三件事:**

1. OceanScale 是什么 → Hero (品牌 + 视觉)
2. 为什么需要它 → 问题 (旧流程 vs 新流程)
3. 它能做什么 → 产品 (4 个能力)

然后留下联系方式 → 联系 (表单)

不做的事: 不教程, 不安装, 不 benchmark 数据, 不 API 文档。这些放 GitHub / docs。

---

## 设计原则

**1. Less is more**
每个 section 只有一个信息焦点。没有段落描述。cards 每张一句话。

**2. 视频/图 carry 内容, 文字 carry 判断**
视觉展示"是什么样", 文字说"为什么重要"。两者互补不重复。

**3. 基础设施美学, 不是海洋浪漫**
NVIDIA GTC / SpaceX 运控风格。线条、网格、暗色、精密。不是蓝色深海梦幻。

**4. 一个视觉高潮, 然后收敛**
Hero 是唯一的"wow"时刻。之后每个 section 更安静、更技术、更聚焦行动。

**5. 所有素材 AI 生成**
Seedance (视频) + GPT-Image-2 (图片)。统一风格: 暗底 #060b12, 品牌青 #2dd4bf。

## 4 个 Section 的设计逻辑

### HERO — "这是谁"

| 要素 | 决定 | 为什么 |
|------|------|-------|
| 视频 | 大规模并行仿真全景 | 展示核心能力 (规模), 不是描述 |
| 文字 | OceanScale | 视频够好就只需要品牌名, SpaceX 模式 |
| 无 CTA | 不放按钮 | 首屏是感受不是行动 |
| 无 eyebrow | 不放分类标签 | 极简 |
| 无 enemy line | 不放问题描述 | 问题放下一屏 |

**效果:** 访客打开页面, 看到震撼的并行仿真画面 + OceanScale。3 秒建立第一印象: "这是一个做大规模仿真的公司"。

### 问题 — "为什么需要"

| 要素 | 决定 | 为什么 |
|------|------|-------|
| 背景 | 暗色 + GPT-Image-2 系统对比图 | 图直接展示"旧 = 串行瓶颈, 新 = 并行规模" |
| 文字 | "真实海洋是最昂贵的测试场" | 一句话 enemy line, 短, 有力 |
| 流程对比 | 旧→新 | 视觉对比, 不用读文字就能看懂 |
| 无 cards | 砍了 4 cards | 系统图已经说完了, cards 重复 |

**效果:** 往下滚, 看到一张对比图: 上面窄管道卡在海试, 下面成千上万并行轨迹。一眼理解"旧方法慢, 新方法快"。一句话强化。

### 产品 — "它能做什么"

| 要素 | 决定 | 为什么 |
|------|------|-------|
| 背景 | 纯暗色 + 微弱网格 | Hero 和问题已经用了视觉重量, 这里安静下来让 cards 说话 |
| H2 | "面向水下机器人的虚拟海洋" | 产品定位, 不是功能描述 |
| 4 cards | 物理/规模/传感器/接口 | 核心能力不可省略, 每个 card 一句话 + 配图 |
| card 配图 | GPT-Image-2 生成 | 技术风格, 不是装饰 |

**效果:** 安静的暗色背景上, 4 张 cards 整齐排列。每张 card 有一个技术可视化配图 + 一句话。工程师看到具体能力, 投资人看到产品完整度。

### 联系 — "怎么联系"

| 要素 | 决定 | 为什么 |
|------|------|-------|
| 背景 | 纯暗色 | 不分散注意力 |
| H2 | "在造水下机器人？" | 直接, 对话式, 筛选受众 |
| Intent selector | AUV/ROV/仿真/科研/其他 | 知道谁在联系, 比通用 form 有价值 |
| 无 email 列表 | 改 form | 降低联系门槛, 收集结构化信息 |

**效果:** 最后一屏, 干净的表单。如果前 3 屏说服了你, 这里花 30 秒填一下。

## 不做的事

- 不放 benchmark 数据 (本地实测不是营销材料)
- 不放安装命令 / pip install
- 不放 Colab 链接
- 不放对比表 (没有实测数据支撑的 checkmarks 没有说服力)
- 不放大段文字描述
- 不用已有旧素材 (风格不统一)
- 不用多个视频 (一个就够)
- 不放 section 编号 (/01, /02...)
- 不放 "AUV 与 ROV" (用 "水下机器人")
